# 开发与验证

使用 Node.js 24、npm、PowerShell 7。

```powershell
npm ci
npm test
npm run typecheck
npm run build
node scripts/qa-workspace.mjs
```

界面验收脚本启动 127.0.0.1:5174，使用独立 SQLite 和模拟模型，通过真实上下文、对话、审核及写入服务处理请求。不会读取个人故事数据库或调用付费模型。

## 领域与服务

- shared/types.ts、requests.ts：工具区分的请求、只读结果、ChangeSet、额外设定／大纲节点、走向状态及多模态消息。
- shared/tools.ts：两种模式独立的工具规则、提示与权限范围。
- main/context.ts：有效故事依据、图片读取与去重、预算、实际请求预览。
- main/conversations.ts：模式与目标隔离、多轮分支、来源快照、检查批次及完整性。
- main/changes.ts：结构化建议解析、领域权限与版本校验、事务写入。
- main/planning.ts：额外设定与大纲独立编辑、排序、历史恢复和章纲关联。
- main/exploration.ts：走向保存、来源指纹校验及幂等创建下一章。
- main/document-edit.ts：使用与编辑器一致的 schema 按文档位置替换选区。
- main/workspace-handlers.ts：严格 IPC 参数校验，供应用与隔离验收复用。
- renderer：统一工作台、额外设定条目与大纲树编辑器、走向卡片、分域候选区及红绿差异审核。

## 验收范围

新测试围绕产品规则重建，不以旧测试名称或原测试数量衡量完成度。覆盖所有工具的完整基础资料和真实图片载荷、脑暴排除正文、领域权限、只读结果、开篇与追加边界、重复文本和跨段富文本、过期与重复采用、部分采用、事务回滚、检查的准确引用和失败覆盖、模式与历史隔离、重启恢复、自动保存及独立的图片／备份功能。

模型 API 协议通过本地 HTTP 模拟验证。流式响应缺少完成标记、返回长度限制或被中断时，不能产生可采用结果。生产供应商的模型能力应按其说明配置，不根据模型名称猜测看图能力。

## 本轮验证记录（2026-11-07）

- 自动化测试：18 个文件、250 项通过；类型检查和生产构建通过。
- 本次隔离验收：长篇完成树形章纲下批量生成场景、差异审核采用、关联规划展示和额外设定隔离；自由探索完成续写审核后自动生成 3 个走向、编辑走向、一键建章及下一章审核后再次生成走向，检查来源全文与最终写作要求，设置中选择 5 个。
- 隔离界面验收：两种模式分别完成脑暴、设定、额外设定、空章开篇、文末续写、选区打磨和故事检查；另验证记忆、命名及插画提示词。
- 请求预览核对完整故事依据、参考图缩略图、额外设定约束、大纲父节点和关联章节；实际模拟请求断言基础资料完整且脑暴不自动携带正文。
- 验证红绿差异与选区采用、额外设定采用后的即时刷新、未保存编辑的冲突提示、候选整组及单条折叠恢复、模式和对话隔离、页面刷新后恢复。
- 检查报告覆盖两章及一组跨章对照；验证 1100px 窗口布局、模型视觉能力与预算字段。浏览器未记录警告或错误。没有使用真实付费 API，也没有读取个人数据库。

连续性和人物弧线检查为了核对全部章节组合，当前需要 n(n+1)/2 次模型调用；节奏检查需要 n 次。界面在生成前显示实际次数，长书可选择部分章节控制范围。失败批次仍在报告中列出，不能视为完整检查。

## 数据版本

数据库继续使用 PRAGMA user_version=2，本次大纲与探索更新复用现有数据与节点 ID，无需重建。早于版本 2 的开发结构仍由既有格式检查拒绝。开发验收使用 STORYBOOK_DATA_DIR 指向隔离目录。数据目录的图片布局版本独立于领域数据库版本。
