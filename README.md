# 页间 · Between Pages

围绕原创角色（OC）的 AI 故事创作桌面应用。

只给角色、能力或世界关键词就能开始冒险，也可以先准备完整设定再逐章创作。故事写起来后，随时完善人物、世界和剧情方向，让新增设定指导后续发展。

文字与插画服务均由你配置接口地址、API Key 和模型，故事与素材保存在本地。当前提供 Windows x64 便携版。

## 功能

### 故事创作

- **两种创作模式**：自由探索与长篇创作。
- **即兴开篇与续写**：一句“去废土世界冒险”即可开始，故事名和本章计划可稍后补充；支持继续当前章或进入下一章。
- **创作自由度**：自由发挥、适度补全、遵循设定，随时切换。明确的角色能力、固定规则和已发生事实始终优先。
- **故事蓝图**：编辑故事想法、世界设定、文风偏好、整体大纲与本章计划。
- **逐章写作**：生成或续写正文、改写选中文段、重写章节、调整后续走向、检查前后矛盾。
- **草稿与版本**：生成结果先进入独立草稿区，可编辑后追加或替换正文；支持章节快照、版本查看与恢复。
- **自动保存**：正文、创作计划和模型配置自动保存，保存失败时可重试。

### 创作资料与记忆

- **独立资料库**：管理 OC、世界观与零碎灵感；创建故事时复制资料，每个故事的修改互不影响。
- **自由分区**：分别记录概述、固定规则、能力、性格、关系等内容，分区名称与内容可自行编辑。
- **边写边完善**：工作台的「完善设定与蓝图」可从零构思，也可结合已采用章节提炼人物与世界；区分正文依据和新增构想，按分区编辑、采用，支持撤销上次更新。
- **文档导入**：支持 TXT、MD、Markdown 多文档导入，完整保留原文；可让模型整理为可编辑草稿，核对来源与待确认事项后再应用。
- **参考内容可见**：关键规则与「始终参考」分区优先完整装入上下文，其余资料按相关性选择；生成前可查看实际参考内容和覆盖情况。
- **正式记忆**：从已采用版本提取事实、角色状态、关系、认知和伏笔，保留来源。修改早期采用章节时，相关自动记忆会停用，后续采用章节会标记待复核。

### 模型与插画

- **自配模型服务**：兼容 OpenAI 风格接口，文字与生图的地址、Key、模型独立配置。
- **模型列表**：获取模型列表、搜索、手动勾选或添加模型，选择默认模型；配置自动保存。
- **可编辑 AI 职责**：开篇、续写、设定完善、脑暴、规划、改写、检查和插画构思等任务均可修改详细提示词，分别指定文字模型。
- **故事插画**：从故事生成绘图提示词，或自行输入提示词；支持角色参考图、图片收藏与导出。默认生图模型为 `gpt-image-2`，可修改为服务商使用的名称。
- **导出与备份**：导出 Markdown / TXT 正文、导出图片、创建完整 ZIP 备份，以及迁移数据目录。

## 开始使用

如果仓库的 Releases 已发布 Windows 便携包，下载 ZIP 后完整解压，运行其中的 `页间.exe`。请保留同目录中的运行文件，不要只移动 EXE。

也可以按照下方的开发说明从源码启动或自行打包。

1. 打开 **设置 → 模型设置**，填写文字服务的接口地址和 API Key。
2. 点击 **获取模型列表**，勾选需要的模型并选择默认项。接口、Key 和模型选择自动保存；可用 **测试模型连通性** 验证文字服务。
3. 在 **创作资料** 添加角色与世界观，直接填写或导入设定文档。使用 **AI 整理文档** 后，先核对结果，再应用并保存资料。
4. **新建故事**，选择创作模式和需要带入的资料，填写最初的想法。
5. 在故事工作区修改蓝图、本章计划与正文，使用右侧 **AI 创作** 生成内容，确认后写入。
6. 满意后 **采用当前章节**，再 **整理正式记忆**。需要插画时，配置生图服务并前往 **故事插画**。

API Key 会回填到密码输入框中；删空输入框即保存为空。资料整理结果和生成正文均需要作者确认，才会写入对应内容。

**设置 → 软件设置** 集中管理数据目录、备份及窗口行为。点击右上角 `×` 时可选择最小化到系统托盘或关闭程序，并勾选「记住我的选择」；可随时将关闭动作改回「每次询问」。收起到托盘后生成任务继续运行，点击托盘图标可恢复窗口，右键菜单可打开或退出页间；选择退出会先停止任务并保存当前内容。标题栏的 `−` 按钮仍然最小化到任务栏。

## 接口兼容

| 用途     | 接口                       | 说明                                         |
| -------- | -------------------------- | -------------------------------------------- |
| 模型列表 | `GET /models`              | 读取 `data[].id`；服务不支持时可手动添加模型 |
| 文字生成 | `POST /chat/completions`   | 支持 SSE 流式响应和非流式 JSON 响应          |
| 图片生成 | `POST /images/generations` | 不携带参考图时使用                           |
| 图片编辑 | `POST /images/edits`       | 携带参考图时使用 multipart `image[]`         |

接口地址支持基础地址，例如 `https://api.example.com/v1`，也支持对应的完整端点。服务需支持 Bearer API Key 认证及上述兼容协议。

应用不内置真实 Key，也不提供模型额度。模型名称、图片尺寸、质量与参考图功能需要服务端支持；文字连通性测试会实际调用所选文字模型。生图在手动点击生成后请求，图片不会自动成为故事事实。

## 本地数据

开发时默认保存到项目下的 `data/`；便携版默认保存到 EXE 旁的 `data/`。使用设置中的目录迁移功能后，以自选目录为准。软件目录需要有写入权限。

```text
data/
├── data-layout.json      # 存储目录版本（当前为 2）
├── database/
│   └── storybook.sqlite   # 故事、资料、草稿、版本、记忆、模型配置与 API Key
├── assets/               # 持久素材，数据库保存相对路径
│   └── images/
│       ├── references/   # 作者上传的设定与参考图
│       │   ├── library/  # 从独立资料库上传
│       │   └── stories/<故事ID>/
│       └── illustrations/
│           └── stories/<故事ID>/  # 故事生成的插画
├── backups/              # 完整备份 ZIP
├── exports/              # 默认导出位置
├── runtime/              # 可重建的 Electron 缓存、日志与 tmp 临时文件
└── settings/             # 预留配置目录
```

图片文件以稳定 ID 命名，故事改名不会改变路径。资料库与故事可以共享图片引用；目录表示图片最初保存的位置，删除故事时会保留其他资料仍在使用的图片。新增素材类型可在 `assets/` 下扩展独立目录。

旧版平铺的图片会在新版启动时自动整理，迁移前先生成数据库与素材备份；缺失文件保留原记录，未知文件保留原位置，不会猜测归属后删除。详见 [数据存储与恢复](docs/STORAGE.md)。

**API Key 明文保存在本地数据库中，完整备份也包含 Key。** 本仓库的 `.gitignore` 已排除数据目录、数据库、目录定位文件、测试资料和打包产物。源码提交与应用数据应分开管理，便携包可作为 GitHub Release 附件发布。

故事和资料保存在本地；执行 AI 任务时，所需的资料、正文或参考图片会发送到你配置的服务。单纯导入文字文档不会请求模型。

### 备份与恢复

- **备份**：在设置中点击「创建备份」，可在应用运行时生成数据库、全部素材、`settings/` 与目录版本文件的 ZIP。运行缓存、历史备份与导出文件不放入 ZIP；如需全部保留，彻底退出软件（包括系统托盘）后，打包整个实际数据目录即可。
- **恢复**：先彻底退出应用并保留现有数据目录副本，再将同一份 ZIP 的全部内容解压到一个新的数据目录。不要混用不同快照的数据库及其 `-wal`、`-shm` 文件；不要手工重排素材目录。
- **迁移**：在设置中选择空目录，应用复制数据并重启；原目录保留。自选目录通过程序旁的 `data-location.json` 定位，移动程序时需一并保留该文件并确保路径可用。

## 开发

推荐环境：**Node.js 24 LTS、npm、Windows 10 / 11 x64**。Windows 下推荐使用 PowerShell 7。当前打包配置和桌面验证面向 Windows，其他系统尚未验证。

### 安装与启动

获取源码后，在项目目录执行：

```powershell
npm ci
npm run dev
```

`npm ci` 使用仓库中的 `package-lock.json` 安装依赖，首次安装需要下载 Electron 等依赖。应用启动后在设置页填写服务信息，无需创建 `.env`。

### 检查与构建

```powershell
npm run typecheck   # TypeScript / Vue 类型检查
npm test            # 自动化测试
npm run build       # 构建主进程、预加载与渲染进程
npm run pack:win    # 构建 Windows 程序目录
npm run dist:win    # 构建 Windows 便携 ZIP
npm run icons       # 品牌 SVG 修改后，重新生成 Windows ICO 与窗口 PNG
```

程序目录默认输出到 `release/win-unpacked/`，ZIP 名称为 `BetweenPages-<版本>-win-x64.zip`。构建产物不提交到源码仓库。

测试覆盖自动保存、模型配置、文档整理、上下文选择、章节版本、记忆有效性、接口协议及备份恢复，使用本地模拟数据，无需真实 API Key。

### 技术栈

| 层级           | 技术                                              |
| -------------- | ------------------------------------------------- |
| 桌面运行时     | Electron                                          |
| 界面           | Vue 3、TypeScript、Pinia、Vue Router、Naive UI    |

## 当前范围

- 资料与记忆使用段落、关键词及近期内容选择，**不要求向量模型或外部知识库**。
- 修改蓝图会改变后续创作计划，已有正文需要结合连续性检查手动复核；目前不会自动重写整本作品。
- 暂不支持 PDF / Word 设定导入、复杂分支树、云同步或无人值守整本生成。
- 模型服务的实际输出效果、参考图一致性和扩展参数支持取决于所选服务与模型。
